# 生成式插图（ImageGen）

**什么时候读**：`outline.md` 该章写了「插图描述」时，**开发这一章之前**读。
没写插图描述的章节完全不用管这份文件。

---

## 0. 产出定位与边界（先读这条，最容易做错）

要产出的是**跟主题同一套简报视觉语言的场景插图** —— 拿
`theme.json` 的 `styleReference` 当画风锚，让每一章的图看起来都属于同一支
片子，而不是随手一张通用 AI 图。

> **生成的是插图图层，不是整张投影片。**
>
> 标题 / 清单 / 数字 / 总结文字**一律留在 HTML**。原因有三条，每条都是既有红线：
>
> 1. 文字要跟着 step **逐步揭示** —— 烧进图里就只能一次全出
> 2. 颜色和字体家族**必须走主题 token** —— 图里的文字换主题就破
> 3. 生成图的文字在 1920×1080 录屏下**必糊**，还常拼错
>
> 所以：参考图的「**版式**」由封面章节用 HTML 复刻（见
> [`CHAPTER-CRAFT.md`](CHAPTER-CRAFT.md) 的「封面章节（00-cover）」），
> 参考图的「**画风**」由这里的生图流程复刻。两件事分开做。

---

## 1. 什么该生成，什么不该

| 该生成 | 不该生成（章节自己用 CSS / SVG / Canvas 画） |
|---|---|
| 人物在做某件事（讲解 / 协作 / 独立工作 / 争论） | 流程图 / 架构图 / 时序图 |
| 有氛围的场景（工位、会议、深夜、户外） | 数据图（柱状 / 折线 / 排名） |
| 抽象概念的具象隐喻物（一把钥匙、一座桥） | 对比表 / 清单 / 卡片矩阵 |
| 产品 / 器物的形象图 | 终端窗口 / 代码块 / 目录树 / 对话窗 |

右列是 [`CHAPTER-CRAFT.md`](CHAPTER-CRAFT.md)「每章必须有 CSS / SVG /
Canvas / JS 视觉演示」这条底线要求章节**亲手画**的东西。**拿生成图顶替
= 验收不过。** 生成图是画面的**氛围层 / 角色层**，不是演示层。

---

## 2. 先查现成素材，别重复生成

主题 `theme.json` 若声明了 `illustrations`（we-bare-bears 已有三张角色图：
`grizzly-presenting` / `panda-reviewing` / `ice-bear-coding`），**先看这几张
的 `bestFor` 能不能直接命中本步的情境**。能就直接用
`/theme-assets/<filename>`，不要重复生成一张几乎一样的。

新生成的图**必须跟这几张同一套画风** —— 同一支片子里两种画风打架，比没图更糟。

---

## 3. 生成时机

**Phase 2.4 开发该章之前**，不是提前批量生成、也不是边写边补：

- 模式 A / B（主线程）：轮到这一章时，先生成图，再动手写章节代码
- 模式 C（并行 subagent）：**由该章自己的 subagent 生成自己的图** ——
  路径按章节 id 分目录，不会互相覆盖

---

## 4. Prompt 配方（以风格参考图为锚）

```
<风格锚> + <内容：outline 的插图描述原文> + <构图约束> + <negative>
```

### 风格锚 —— 优先喂参考图

主题 `theme.json` 的 `styleReference.path`，实际文件在
`themes/<theme-id>/assets/`（脚手架已复制一份到
`<project>/public/theme-assets/`）。

- **生图工具支持参考图输入** → 直接把这张图喂进去，要求"沿用这张图的画风"
- **不支持** → 用 `styleReference.styleNote` + `descriptionZh` + `mood` 拼成
  文字前缀。以 we-bare-bears 为例：
  > 圆润炭黑手绘轮廓、奶油纸底、天空蓝与蜂蜜木色为主、淡紫／淡黄柔和几何
  > 形状点缀、平涂无写实阴影、角色表情友善的绘本插画风

`illustrations[].altZh`（如"熊猫拿着咖啡阅读笔记"）是现成的**描述语气范本** ——
照那个颗粒度写内容部分就对了。

### 构图约束

- 主体偏置一侧，另一侧留白给 HTML 文字（对齐参考图"右侧插图 / 左侧文字"的布局）
- 背景：透明，或主题的奶油底色（`--surface`）—— 方便合到舞台上不出白框
- 画面内**不得有任何文字**（含招牌、按钮标签、UI 文案）

### Negative

文字 / 水印 / 假 logo / UI 截图感 / 紫粉渐变 / 写实照片风 / 3D 渲染质感 /
杂乱背景。

### 生成后目视比对

把新图和 `styleReference` 及既有三张角色图放一起看：**线条粗细、配色、
留白密度、有没有阴影**四项对不上就重新生成。**不要将就** —— 画风不一致
在录屏里一眼看得出来。

---

## 5. 输出与引用

| | 路径 |
|---|---|
| 落盘 | `presentation/public/illustrations/<chapter-id>/<slug>.png` |
| 章节引用 | `/illustrations/<chapter-id>/<slug>.png` |

`<chapter-id>` / `<slug>` 直接取 outline 插图描述那一行写的值。

与 `/theme-assets/`（主题自带的静态素材）**平行、不混用**：
`theme-assets` 是跟着主题走、换主题会换的；`illustrations` 是跟着这支片子
的内容走的。

---

## 6. 工具无关 + 降级路径

本 Skill 的 `manifest.json` 声明兼容多种 agent（claude-code / cursor /
codex-cli / gemini-cli / opencode），各家生图工具不一样：

1. **优先调用当前 agent 可用的生图工具** —— Claude Code 用 ImageGen，
   其它 agent 用各自的等价工具
2. **调不到 / 生成失败** → **降级**：
   - 章节里放 placeholder 占位卡（按真实比例留位，卡上写"illustration ·
     <一句描述>"）
   - `outline.md` 素材清单该条改标 `⚠️`（待提供）
   - **交付本章时明确告诉用户"这张图没生成出来，现在是占位卡"**

降级是**允许的**，隐瞒不是。这条对齐
[`CHAPTER-CRAFT.md`](CHAPTER-CRAFT.md)：**缺的东西承认缺，比 fake 强一百倍。**

---

## 7. 生成后回写 outline

生成成功 → `outline.md` 末尾「素材清单」里对应那条
`🎨 …（待生成 → …）` 就地改成：

```
- ✓ <描述>（`illustrations/<chapter-id>/<slug>.png`）
```

**不回写 = 下一个 agent 会以为还没生成，重复跑一次生图。**
