# `outline.md` 格式 spec

影片章節規劃的產出檔案。**使用者可以直接編輯**，所以格式必須人類友善
（用 markdown 不用 JSON / YAML）。

!重要：閱讀此檔案後必須繼續閱讀 [`CHAPTER-CRAFT.md`](CHAPTER-CRAFT.md) 的全部內容，了解對網頁效果的真實需求，然後再開始撰寫 outline

> ## ⚠️ outline 是開發計畫，不是視覺規劃
>
> outline 只規劃**節奏 + 內容 + 資訊密度**：
>
> - 章節切分 / 每章 step 數 / 每步估時
> - 每步畫面內容（hero / 標語 / 數據 / 列表項）
> - 章節級**資訊池**（從 article 抽的數字 / 引用 / 案例 / 標籤）
> - 章節級**插圖描述**（選填 —— 需要具象圖時才寫）
>
> 外加一件不屬於「規劃」但必須寫進檔案的東西：**頂部「進度看板」** ——
> 讓換 agent / 接續 session / 平行 subagent 都知道流程走到哪一步。
>
> **outline 裡的 step 數是初始預估**。最終 step 數以章節實作時的
> `narrations.ts` 為準——後者既是 step 數來源，也是音檔合成來源
> （詳見 [`CHAPTER-CRAFT.md`](CHAPTER-CRAFT.md)「程式碼層最小限制」+
> [`AUDIO.md`](AUDIO.md)）。如果實作時章節 step 數和 outline 不一致，
> 回過來同步 outline 即可，不需要糾結「對得嚴絲合縫」。

> **寫 outline 前必讀**（雙來源原則，[CHAPTER-CRAFT.md 原則 10](CHAPTER-CRAFT.md#雙來源節奏跟旁白稿細節回原文章)）：
>
> - **`script.md`** —— 決定**節拍**：依 `---` 切節拍，每節拍 1~2 step、估時
> - **`article.md`**（如有）—— 決定**畫面資訊密度**：每章首段抽**資訊池**

## 抽象範例（看格式）

````markdown
# Video Outline

> **主題**：`<theme-id>`（Checkpoint Plan 已選定）—— <一句話風格描述>
> **總時長**：約 <T> 分 <S> 秒（旁白 ~<X> 字 ÷ 4 字/秒）
> **章節數**：封面 + <N> 章 / <M> 步

---

## 進度看板

<!-- agent 每次接手先讀這一段；每過一個硬節點立刻回寫，不可延後。 -->

| # | Checkpoint | 狀態 | 備註 |
|---|---|---|---|
| CP-0 | 內容自我檢查（script.md / outline.md） | ⬜ | |
| CP-1 | Checkpoint Plan（稿子 / outline / 主題 / 素材 / 模式） | ⬜ | 主題：— ／ 開發模式：— |
| CP-2 | 封面 + 第 1 章驗收（硬節點） | ⬜ | |
| CP-3 | 第 2~N 章驗收 | ⬜ | 見下方章節狀態 |
| CP-4 | Checkpoint Audio（是否合成音檔） | ⬜ | |
| CP-5 | Phase 4 錄影路徑確認 | ⬜ | |

| 章節 | 狀態 | 備註 |
|---|---|---|
| 00-cover | ⬜ | |
| 01-<id> | ⬜ | |
| 02-<id> | ⬜ | |

狀態詞彙（固定，不得自創）：⬜ 未開始 ／ 🟡 進行中 ／ 🔵 待使用者驗收 ／ ✅ 已通過 ／ ⏭️ 已跳過

---

## 0. 00-cover — 封面（<S> steps · ~<T>s）

**資訊池**：
- 標題：<主標題> ／ 副標題：<副標題> ／ 講者或出處：<...>

**開發計畫**：

- step 1 (~Ts) — <封面構圖：主標題 / 副標 / 講者 / 視覺錨點>
- ...

---

## 1. <chapter-id> — <章節標題>（<S> steps · ~<T>s）

**資訊池**（chapter agent 依需求掛角標 / 副標 / pull-quote / mono cue）：
- <類型：數字 / 引用 / 出處 / 案例 / 詞義 / 時間 / 對比 / ...>：<內容> —— <來源 article §X / Lxx>
- ...

**插圖描述**（選填 —— 寫了就必須在開發本章前生成素材）:
- [step 3] <要畫什麼、誰在做什麼、構圖重點，一句話> → `illustrations/<chapter-id>/<slug>.png`

**開發計畫**：

- step 1 (~Ts) — <畫面內容>
- ...

旁白節選：
> <1~3 句節選，對應到 script.md 完整文字>

---

## 2. <chapter-id> — ...
````

> **關於時長**：outline 裡**只**寫 step 的 `(~Ts)` 旁白估時（影音對齊
> 用），**絕對不寫**動畫時長 / 錯開時間量 / keyframe 數值。這些都在章節開發
> 階段決定（[`CHAPTER-CRAFT.md`](CHAPTER-CRAFT.md) Part 3 時長參考）。

> - 科技評測類（實測 / 對比 / 跑分） → [`EXAMPLES/case-tech-review/`](EXAMPLES/case-tech-review/)

## 欄位慣例

### 頂部 metadata block

用引用區塊（`>`）形式，方便掃一眼整體規模：

| 欄位 | 必填 | 說明 |
|---|---|---|
| **主題** | ✓ | Checkpoint Plan 必須已確認。chapter agent 實作時依主題顏色 / 字體 token 走，動畫 / 節奏 / 視覺演示由章節自由發揮 |
| **總時長** | ✓ | 估算旁白時長（中文 ~ 250 字 / 分鐘） |
| **章節數** | ✓ | `封面 + N 章 / M 步` |

### 進度看板（**必填，位置固定在 metadata 之後**）

這是**跨 agent 的唯一進度真相來源**。寫 outline 時就要把整張表建好（全部 ⬜），
之後每過一個硬節點由當時的 agent 回寫。詳細協定見
[`SKILL.md`](../SKILL.md) 的「進度看板協定」。

| 規則 | 說明 |
|---|---|
| **兩張表** | 上表 = 六個 checkpoint（CP-0 ~ CP-5，編號 / 名稱固定不得改）；下表 = 逐章狀態 |
| **章節表與下方章節一一對應** | 含 `00-cover`。章節增刪時兩處同步 |
| **狀態詞彙固定** | ⬜ 未開始 ／ 🟡 進行中 ／ 🔵 待使用者驗收 ／ ✅ 已通過 ／ ⏭️ 已跳過 —— **不得自創** |
| **備註欄** | CP-1 記「主題 / 開發模式」；其餘記關鍵決定（如「使用者要求第 3 章重做節奏」） |
| **不寫時間戳記** | agent 拿不到可靠時間；要記順序就靠表格本身的先後 |

### 章節標題：`## N. <id> — <title>（<S> steps · ~<T>s）`

| 部分 | 規則 |
|---|---|
| `N` | **封面固定為 `0`**，內容章節從 `1` 起遞增，對齊 `chapters.ts` 的註冊順序 |
| `<id>` | **小寫 + 連字號**。會成為 React `key` / 資料夾名 (`src/chapters/0N-<id>/`) / 音檔子目錄 (`public/audio/<id>/`) |
| `<title>` | 給人看的中文標題。**不會**進 React 程式碼 |
| `<S> steps` | 該章 step 總數 |
| `~<T>s` | 該章旁白總估時（中文 ~ 4 字/秒） |

合法 id：`coldopen`、`hook`、`why-good`、`why-good-text-render`。
不合法：`why_good`（要用連字號）、`Hook`（要小寫）、`第一章`（要拉丁字元）。

> **第一個章節固定是封面**：`## 0. 00-cover — 封面（1~2 steps · ~Ts）`，
> 資料夾 `src/chapters/00-cover/`。內容章節從 `01-` 起編號。封面規格
> （必須有什麼 / 版型怎麼決定）見
> [`CHAPTER-CRAFT.md`](CHAPTER-CRAFT.md) 的「封面章節（00-cover）」。

### 章節首段「資訊池」（**雙來源原則核心落地**）

每章獨立列出從 `article.md` 抽的細節集合，**讓 chapter agent 實作每步
畫面時依需求取用**——可能掛成右下角 mono 角標 / 副標小字 /
pull-quote 引用 / 資料浮層。

#### 資訊池條目格式

```
- <類型>：<具體內容> —— <來源 article §X / Lxx 或簡註>
```

> **沒有 article（使用者直接給 script）**：資訊池退化為「主動設計畫面資訊
> 密度」——靠數字 / 對比 / metadata 等讓畫面比旁白資訊密。可以列「畫面
> 裝飾元素池」而非「article 抽取池」。

### 章節「插圖描述」（**選填**，放在資訊池之後 / 開發計畫之前）

某一步真的需要一張**具象場景圖**（人物行動 / 場景 / 隱喻物 / 產品形象）
時才寫。寫了就代表：**開發本章之前必須先呼叫圖片生成工具產出素材**，產物落到
`presentation/public/illustrations/<chapter-id>/<slug>.png`。

```
**插圖描述**（選填 —— 寫了就必須在開發本章前生成素材）:
- [step 3] <要畫什麼、誰在做什麼、構圖重點，一句話> → `illustrations/<chapter-id>/<slug>.png`
```

| 規則 | 原因 |
|---|---|
| 每條必須綁定一個 **`[step N]`** | 生成的圖得知道掛在哪一步 |
| **一個 step 最多一張** | 一步一個聚焦想法，兩張圖就是兩步 |
| **只寫「畫什麼」，不寫「怎麼畫」** | 畫風一律由主題 `theme.json` 的 `styleReference` 決定 —— 同「outline 不寫動畫」的道理，寫死風格 = 生圖退化成翻譯機 |
| **描述裡不得要求圖上出現文字** | 文字留在 HTML 才能逐步揭示 + 走主題 token；燒進圖裡錄影會糊 |
| slug 小寫 + 連字號 | 同章節 id 命名規則 |
| **能用 CSS / SVG / Canvas 演出來的不要寫** | 關係圖 / 流程圖 / 資料圖屬於「視覺演示」，是章節必須自己畫的底線，不能拿生成圖頂替 |

> 完整生圖流程（prompt 配方 / 風格錨點 / 輸出路徑 / 呼叫不到工具時的
> placeholder 降級）見 [`ILLUSTRATIONS.md`](ILLUSTRATIONS.md)。

### Step 列表：每步 **1 行**

```
- step N (~Ts) — <畫面內容>
```

| 規則 | 原因 |
|---|---|
| `step N` 從 1 起算 | agent 實作時 `if (step === N - 1) ...`（注意從零起算的偏移） |
| **`(~Ts)`** 必填 | 依 script.md 本步對應旁白段字數 ÷ 4 估算（中文 ~ 4 字/秒）。範圍 3~10s |
| **畫面內容** | 一句話講清楚這一步舞台上有什麼：hero / 標語 / 數據 / 裝飾元素。**≤ 1 行**，再多就該拆 step |
| **不寫動畫** | 寫死 = 翻譯機化（詳見本檔案頂部框） |
| **不寫時長數值 / 錯開時間量** | 這些在章節開發階段決定 |
| **不寫實作手段** | filter / SVG / Canvas 選型留給 chapter agent |


### 旁白節選（每章末尾，選填但推薦）

精煉 1~3 句，**不是完整稿子**，僅供章節規劃階段對照「這章在講什麼」。
完整文字回 `script.md`。`outline.md` 章節 = `script.md` 中兩個明顯
主題切換之間的段落。

> 音檔合成（[`AUDIO.md`](AUDIO.md)）會**回到 `script.md`** 切分完整
> 文字，**不**用 outline 節選。

## 命名規則速查

| 對象 | 規則 | 範例 |
|---|---|---|
| 封面章節 | 固定 `00-cover` | `src/chapters/00-cover/Cover.tsx` |
| 章節 id | 小寫 + 連字號 | `coldopen`, `why-good` |
| 章節資料夾 | `0N-<id>`（封面 `00-cover`，內容從 `01-` 起） | `src/chapters/01-coldopen/` |
| 章節元件 | PascalCase | `Coldopen.tsx`, `WhyGood.tsx` |
| 章節 CSS 類別前綴 | 章節縮寫（避免跨章衝突） | `.cv-` / `.cd-` / `.wg-` |
| 音檔子目錄 | `<id>/` | `public/audio/coldopen/` |
| 音檔 | `<step-N>.mp3`（從 1 起算） | `public/audio/coldopen/1.mp3` |
| 生成插圖 | `public/illustrations/<chapter-id>/<slug>.png` | `public/illustrations/why-good/three-bears-review.png` |

## 章節切分的經驗法則

- **封面 `00-cover` 不受這條約束** —— 1~2 步就夠，也不計入「每章 3~8 步」
- **每章 3~8 步**。少於 3 步太薄；多於 8 步觀眾會忘記這章在講什麼
- **總時長 ÷ 30 秒** ≈ 章節數（一章約 30~60 秒講完）
- **每章 = 一個聚焦主題**。「為什麼強 + 怎麼用」是兩章，不是一章
- **章節邊界 = 旁白稿裡講者會換語氣 / 換主題的位置**。讀 `script.md`
  時哪裡你下意識想「清一下喉嚨接下一段」，那裡就是章節邊界
- **慢節奏 / 長鏡頭調性**（電影感片頭 / 安靜敘事）每章可少到
  2~3 step；**資訊密集型**（科技評測 / 對比表）每章可放寬到 8~10 step

## 素材清單（outline.md 末尾）

```markdown
## 素材清單

### 0. 00-cover
- ✓ <封面用到的資源> （<已就位路徑>）

### 1. coldopen
- ✓ <資源 1 描述> （<已就位路徑>）
- ⚠️ <資源 2 描述>（待提供）
- 🎨 <插圖描述對應條目>（待生成 → `illustrations/coldopen/<slug>.png`）
```

標記：`✓` 已就位 ／ `⚠️` 待使用者提供 ／ `🎨` 待圖片生成工具產出。
**插圖描述裡的每一條都要在這裡有一條對應的 `🎨`**；生成完成後由 chapter
agent 就地改成 `✓` + 實際路徑（生不出來則降級為 placeholder，改標 `⚠️`
並在交付時明確告訴使用者）。

## 自我檢查（寫完 outline **強制**執行，不可跳過）

> ⚠️ **強制流程**：outline 寫完後**必須**走自我檢查 → 修改 → 提交 三步。
> **禁止**寫完直接進入 Checkpoint Plan 讓使用者對齊。
>
> **執行方式**（依能力降級）：
>
> 1. **優先 Agent Teams**：開一個獨立 reviewer agent，傳入 `outline.md`
>    + 本節自我檢查清單 + `script.md` / `article.md` 路徑，讓它**逐項檢核 +
>    出結論**（哪幾條 fail + 證據）。
> 2. **其次 subAgent**：當前 agent 沒有 Teams 但能開 subagent，用 subagent
>    走同樣流程。
> 3. **都沒有**：自己**嚴格逐項**檢核。
>
> 拿到結論後**先照 fail 項改 outline，再進入 Checkpoint Plan**。

- [ ] **頂部有「進度看板」**：CP-0 ~ CP-5 六列齊全（編號 / 名稱未改），
      章節表含 `00-cover` 且與下方章節一一對應，狀態詞彙都在合法五選一內
- [ ] **第一個章節是 `## 0. 00-cover — 封面`**，內容章節從 `1.` 起
- [ ] 每個 step 都是**單一句畫面內容描述**，沒有「動畫」列 /「手段」列
- [ ] 沒有任何 step 寫了具體毫秒 / 秒數（除 `(~Ts)` 旁白估時）
- [ ] 每章首段都有「資訊池」block，至少 3 條 article 抽取項，**每條
      必帶來源標註**（`—— 來源 article §X / Lxx`）—— 沒標註 chapter agent
      回不到原文
- [ ] **所有 step `(~Ts)` 累加 ≈ 頂部宣告的總時長**（誤差 < 10%）—— 不
      一致說明節奏規劃失真
- [ ] 章節切分符合「每章 3~8 步 / 30~60s 一個聚焦主題」經驗（封面除外）
- [ ] **每條「插圖描述」都綁定了合法 `[step N]`、有 slug、沒要求圖內文字**，
      且不是「能用 CSS / SVG 畫出來的關係圖 / 流程圖 / 資料圖」
- [ ] 末尾「素材清單」分章節列出，✓ / ⚠️ / 🎨 標註清楚，且每條插圖描述
      都有對應的 `🎨` 條目
- [ ] 腳本不得包含標題、序號等非旁白內容，僅包含人類正常可讀的內容

寫完看一眼：**outline 是不是乾淨到 chapter agent 看了能立刻開工 + 還有
設計空間**？是 = 合格。如果你看了都覺得「太空，agent 不知道動畫選什麼」
——**那是對的**，動畫本來就該由 chapter agent 在開發時依
[`CHAPTER-CRAFT.md`](CHAPTER-CRAFT.md) 現場決定。該補的是**畫面內容與
資訊池**（這一步到底演什麼、有哪些細節可掛），不是動畫。
