# 章節開發指引（每章開發必讀）

---

## 封面章節（`00-cover`）

**每支片子的第一個章節固定是封面** —— `src/chapters/00-cover/`，
內容章節從 `01-` 起。它是錄影的第一個畫面，決定觀眾對整片調性的第一印象，
所以跟第 1 章一起在主執行緒做完、一起給使用者驗收（見
[`SKILL.md`](../SKILL.md) 的 2.2）。

**必須有**：

- 主標題
- 副標題
- 講者 / 出處 / 日期（至少一項）

**建議有**：重點清單預告（這支片子會講幾件事）、一句總結句。

**版型怎麼決定**：`theme.json` 的 `layoutReference` 是固定封面版型參考，**先看那張參考圖**
（scaffold 已複製到 `<project>/public/theme-assets/`），照它的 `layoutNote`
用 HTML / CSS 落地。這張圖含版面與文字，**禁止餵給 ImageGen**；插圖畫風另由
`illustrationStyle` 管理。

**仍然受全片紅線約束**：

- 沒有頁首 / 頁尾 / 頁碼 / 品牌條
- 字級大、留白多；顏色與字體家族走 token
- **至少一處動態效果** —— 封面允許以靜態構圖為主（它要讓人看清標題），
  但不能完全沒動作。一條橫線劃出、標題分行錯開進場、角色圖輕輕落位，
  任選一種即可，不要三種都上
- **`narrations.ts` 照樣必須有**。沒有開場旁白就用空字串 `""`，
  Auto 模式會依字數估時撐過去

**封面不受「每章 3~8 步」的經驗約束** —— 1~2 步就夠。

## 這是影片，不是簡報

正在做的是**影片網頁** —— 講者點擊 + 旁白 + 錄影發出去給觀眾看。
判斷每一步做對沒有，標準非常樸素：

- **不像簡報** —— 觀眾感覺是在看影片，不是在看翻頁投影片（頁面中不得包含頁首頁尾，突顯主視覺元素）
- **看起來舒服** —— 配色、字體、節奏都讓人放鬆，不得出現大量的純文字、不得出現字級太小的文字
- **有視覺衝擊** —— 畫面在演事情，不只是文字堆砌，不得一次全部列出所有元素，關鍵元素隨進度逐步推進展現

---

## 必須用 CSS / SVG / Canvas / JS 大膽繪製視覺演示

> **這是底線。**
>
> 每一章都至少要有 1~2 處「動起來的圖 / 演示元素」。
> **整章只有純文字 = 驗收不過 = 回去重做。**
>
> **生成插圖不算數** —— 一張 PNG 是氛圍層 / 角色層，不是演示層。
> 演示元素必須章節自己用程式碼畫。

影片感最強的來源 —— 使用者**看見**了被講解的東西在螢幕上演給他看：

- 數字在遞增 / 橫條在成長 / 排名在交換
- 流程節點依序點亮 / 連線自動繪出
- 對比被一刀切開 / 聚光燈掃過 / 形狀在變形
- 粒子聚攏成形 / 雜訊背景流動 / 字元雨落下
- 模擬終端機互動
- 模擬 AI 對話視窗
- 模擬檔案目錄樹

**怎麼組合發揮都行 —— 但每章必須用，不允許整章純文字。**

## 逐步揭示，禁止一次全部展示

整頁內容由**全域 `step` 計數器**驅動 —— 點擊空白處或按 → 鍵推進
一步。設計每一步時心裡要默念：**這一步演什麼，下一步演什麼**。

**最重要的一條**：

> 當旁白在說「第一是 X、第二是 Y、第三是 Z」這種**清單 / 列表**時，
> **嚴禁**一個 step 把 X / Y / Z 全部 stagger 上來。

正確做法：

- 一項 = 一個 step
- X 只在它自己的 step 裡獨自亮起
- 講到 Y 時，X 灰化保留當作脈絡 + Y 亮起
- 講到 Z 時，X / Y 都灰化 + Z 亮起

**判斷標準**：講者會一個一個唸出來嗎？會 → 必須逐個揭示。

## 內容取捨：抓重點，不要原文搬運

影片是**聲音 + 畫面**：

- **旁白**負責把資訊線性講清楚
- **畫面**負責把節拍重點放大、把節奏感拉出來

每個 step 畫面上只掛這個節拍**最值得放大的 1~3 個東西** —— 一個
hero 標語 / 一個數字 / 一組對比 + 必要的視覺演示。

不要試圖把原文每個字都搬上去。那是論文閱讀，不是影片。

---

## 雙來源：節奏跟旁白稿，細節回原文章

> **節奏 / 順序 / 節拍切分** 跟 **`script.md` 旁白稿** —— **關鍵順序不能亂**。
> **畫面細節 / 數據 / 引用 / 案例** 回 **`article.md` 原文章**抽。

`outline.md` 已經在每章首段抽了「資訊池」做參考。但**實作章節時
也必須回去翻 `article.md` 本章對應段落** —— 那裡有比旁白稿多得多的
細節（具體數字、引用原話、案例面向、出處時間）。把這些掛到畫面上，
讓**畫面資訊密度 > 旁白資訊密度**。

> **如果你只用了旁白稿的內容做章節** —— 畫面等於把旁白打字打了一遍
> —— 那就是簡報，不是影片。
>
> 章節實作一定要回原始文章抽細節，不要嫌麻煩。

---

## 字體 / 配色 / 動畫 / 留白 —— 影片演示基本美感

影片觀眾離螢幕遠、注意力浮動，所以：

- **字級要大** —— hero 文字至少 80px 起，遠看也能看清
- **留白要多** —— 舞台四邊都要讓出大留白，畫面不要塞滿
- **配色要舒服** —— **顏色和字體家族必須用熊熊主題 token**（避免章節漂移）；
  字級 / 間距 / 時長這些章節依內容自由發揮（詳見下方「程式碼層最小限制」）
- **動畫要舒服 + 有質感** —— 出現得乾淨俐落，停下來不搶戲；有質感靠
  **設計巧思**（內容驅動的演示動畫），不靠**速度暴力**或**密集閃爍**

### 熊熊視覺一致性

這個 Skill 固定使用 `we-bare-bears`。章節可依內容設計不同動作，但調色盤、
字體個性、紙卡材質、手繪輪廓、角色比例與插圖畫風必須一致。平行開發也不能把
「章節自由」解讀成另一套風格；第 1 章程式碼與 `theme.json` 是共同視覺契約。

---

## 避免 AI 味

AI 生成的網頁有幾種共通的「視覺指紋」，**全部不要**：

- 紫粉 / 藍紫對角漸層背景
- 圓角卡片 + 彩色左邊框裝飾
- 漸層按鈕 + 大圓角膠囊
- emoji 當圖示用
- 假資料 / 假 logo / 假「X 萬使用者」
- 整章 N 步用同一種進場動畫（全場 fade / 全場 blur）
- 每步都掛 ken burns / 光暈呼吸 / 持續閃爍
- 每個畫面右下角都掛 mono 角標 / 序號
- 生成插圖裡帶文字 / 假 logo / 拼錯的招牌字（文字一律留在 HTML，
  見 [`ILLUSTRATIONS.md`](ILLUSTRATIONS.md)）

缺的東西**承認缺** —— 用 placeholder 佔位卡（一張寫著「image · 16:9
描述」的卡片，依真實比例留位）。**不要**用 emoji 湊、不要找無關圖湊、
不要編數字。**沒有就承認沒有**，比 fake 強一百倍。

## 框架已經搭好的部分（理解就好，不需重寫）

- **16:9 固定舞台**：內容設計在 1920×1080 上，外層 transform scale
  縮到任何視窗大小，外圍 letterbox 留黑 —— **沒有響應式斷點**
- **舞台置中 + 大留白**：上下左右四邊都讓出至少 80px 的安全區
- **隱形章節導覽**：畫面底部預設完全透明，滑鼠移到底部邊緣才出現
  橫向章節列；最左側清單 icon hover / focus 後展開全部章節總覽，兩處都
  支援點擊跳章（錄影時鏡頭看不到任何 chrome 控制項）。導覽的顏色、字體、
  表面、邊框與陰影必須走當前主題 token，不得保留通用播放器風格
- **全域 step 驅動**：點擊舞台空白處 / 鍵盤 ←/→ 推進；章節是 `step`
  的純函式，沒有計時器、沒有命令式狀態
- **資源預載窗口**：`PrefetchAhead` 會把接下來 3 個 step 先 render 到一個
  永遠不掛進文件的容器，讓瀏覽器提前把圖抓進快取 —— 切 step 時圖片已經在
  本機，不會「慢一拍」才出現（插圖放 `public/`、URL 在執行期才組出來，
  Vite 建置期看不到它們，產不出 preload 提示，所以需要這一層）。章節什麼
  都不用做，但**這是章節必須保持純函式的原因**，見下方工程紅線

## 程式碼層最小限制

不能踩的紅線，其它怎麼寫都行：

### 必須用 token（避免熊熊風格漂移的底線）

- **顏色**：`--shell` / `--surface` / `--surface-2` / `--surface-3` /
  `--text` / `--text-2` / `--text-mute` / `--text-faint` / `--rule` /
  `--accent` / `--accent-soft` / `--accent-glow` ——
  **禁止寫死 hex / rgb / 顏色名**
- **字體家族**：`--font-display-cn` / `--font-display-en` / `--font-body`
  / `--font-mono` —— **禁止寫死字體名**
- **主題個性簽名**透過 primitive class 自動接入，**不要在章節 CSS 裡
  重新定義它們**：
  - `.hero-num`（hero 數字風格 —— 主題決定襯線 / 等寬 / 粗黑）
  - `.rule`（分隔線 —— 主題決定 1px 實線 / 4px 實線 / 2px 虛線）
  - `.card`（卡片 —— 主題決定圓角 + 陰影個性）
  - `.stage-frame`（舞台底色 / 圓角 / 陰影 / 裝飾圖樣 / vignette
    全自動，章節什麼都不用做）

### 可寫死 / 可用 token，依內容自由（解鎖章節自由設計）

- **字級**：想要 80px 就寫 80px，想用 `var(--t-h1)` 也行
- **間距 / padding / margin**：依畫面節奏寫具體值
- **動畫時長 / 緩動 / keyframe**：依動畫意圖寫具體值
  （**節奏調性**參考 `theme.json` 的 `mood` —— 慢主題別寫 200ms 的快動畫）
- **邊框寬度 / 非個性圓角 / 字距**：隨手寫
- **gap / grid 版面尺寸**：依畫面構圖寫

### 其它工程紅線

- 不用 `setTimeout` / `setInterval` 驅動動畫 —— 用 CSS keyframes
- **章節元件必須是 `step` 的純函式**：不要 `useState` / `useEffect` /
  `useRef` / 計時器 / 網路請求。除了可讀性，這是 `PrefetchAhead` 的硬
  前提 —— 它會把未來幾個 step 的元件在畫面外多 render 一份來預熱圖片，
  有副作用的章節等於被執行兩次。真的需要狀態，就把該 step 拆成兩個 step
- **章節裡的 `<img>` 不要加 `loading="lazy"`**：預載窗口靠的正是瀏覽器對
  畫面外 `<img>` 的積極載入，`lazy` 會讓預載整段失效，退回「切到該頁才
  開始下載」
- 章節內的可互動元素（按鈕 / 自訂控制項）加 `data-no-advance`，
  否則點了會被舞台誤推進 step
- 章節程式碼物理隔離：每章獨立資料夾、獨立 CSS 類別前綴，不跨章 import
- **每章必須有 `narrations.ts`**（與 `<Chapter>.tsx` 同目錄）：
  - 陣列長度 **=** 章節程式碼裡 `if (step === N)` 出現的最大 N + 1
  - 每個元素 = 一個 string，該 step 要播的旁白文字（來自 `script.md`
    對應段落，**語意一致**——可微調標點 / 斷句以配合 TTS，但不能漏關鍵詞句）
  - 完全沒有音檔的過場 step 用空字串 `""`，Auto 模式會依字數估時撐過
  - 這是**音檔合成 + Auto 模式自動推進的唯一真相來源**，寫錯或漏寫
    會讓錄影對不上嘴
- **動畫時長必須 ≤ 該 step 的旁白時長**——Auto 模式嚴格依音檔結束推進，
  沒有「等動畫跑完」的保底。動畫太長 → 三選一：**寫更長旁白 / 拆 step
  / 調動畫速度**。詳細機制見 [`AUDIO.md`](AUDIO.md)

## 完工自我檢查（寫完每章**強制**執行，不可跳過）

> ⚠️ **強制流程**：章節實作完成後**必須**走完下面的自我檢查 → 修正 → 回報
> 三步。**禁止**「實作完成 → 直接回報給使用者」。
>
> **執行方式**（依能力降級）：
>
> 1. **優先 Agent Teams**：開一個獨立的 reviewer agent，傳入本章程式碼路徑
>    + 本檔案 Part「完工自我檢查」清單，讓它**逐項檢核 + 出結論**（哪幾條
>    pass / 哪幾條 fail + 證據）。
> 2. **其次 subAgent**：當前 agent 沒有 Teams 能力但能開 subagent，用 subagent
>    走同樣的流程。
> 3. **都沒有**：當前 agent 自己**嚴格逐項**檢核，不允許目視掃一遍就放行。
>
> **拿到自我檢查結論後**：先照 fail 項**改完程式碼**，然後再向使用者回報「做完
> 了 + 自我檢查結論 + 改了什麼」。**直接拿原始結論回報但不修正 = 違規**。

寫完一章 + 在瀏覽器點完一遍後逐項過：

- [ ] **每章至少 1~2 處 CSS / SVG / Canvas / JS 視覺演示** —— 沒有 = 回去補
- [ ] **不同 step 的主導動作不一樣** —— 全章一種動畫 = 回去重做
- [ ] 字級大、留白舒服、配色舒服
- [ ] 清單 / 列表逐個揭示，**1 項 = 1 step**
- [ ] 畫面資訊比旁白稿多（回了原文章抽細節掛上來）
- [ ] 沒有紫粉漸層 / 圓角彩色邊框 / emoji / 假資料 / 假 logo
- [ ] 缺的素材用 placeholder，不是 fake
- [ ] **outline 在 CP-1 保留的「插圖建議」全部已生成並接入**，或已降級為 placeholder
      **且交付時明確告訴了使用者**；`outline.md` 素材清單已回寫（`🎨` → `✓` / `⚠️`）
- [ ] **生成插圖使用 `illustrationStyle.goldenReference` + 本次角色 reference，
      且畫風與既有 `illustrations` 一致**，
      且圖內沒有任何文字 —— 不一致就重新生成，不將就
- [ ] **封面章節（若本次做的是 `00-cover`）**：主標題 / 副標題 / 講者或出處
      齊全，至少一處動態效果，無頁首頁尾
- [ ] **顏色和字體家族全部走 token**（無寫死 hex / 字體名）；hero 數字
      / 卡片 / 分隔線 / 舞台用 primitive class 接入主題個性 —— 這兩條不
      達標 = 跨章風格會破
- [ ] 章節交付時**主動告訴使用者**：「本章還缺這些素材」
- [ ] 禁止出現小字級字體、大量純文字（出現後必須回去改）
- [ ] 禁止出現任何形式的頁首頁尾，僅展示關鍵內容（出現後必須回去改）
- [ ] **`pnpm exec tsc --noEmit`（或 `npx tsc --noEmit`）通過** —— 不通過禁止回報「做完了」
- [ ] 章節程式碼物理隔離：獨立 CSS 類別前綴（`.cd-` / `.mg-` / ...），
      未跨章 import，未修改 `chapters.ts` 之外的共用檔案
- [ ] **`narrations.ts` 存在**且 `narrations.length` === 章節程式碼裡
      `if (step === N)` 用到的最大 N + 1（不一致 = Auto 模式錄影會錯位）
- [ ] **每條 narration 文字與 `script.md` 對應段落語意一致**（關鍵詞句 /
      數字 / 引用全部保留，可為 TTS 微調標點斷句）—— 錄影旁白應當能被
      觀眾聽成同一段稿子
- [ ] **每個 step 的視覺動畫時長 ≤ 旁白時長**（旁白 `字數 ÷ 4` ≈ 秒數）—— 
      超出會被 Auto 模式當場切斷，動畫演到一半就跳下一步

再執行機械驗證；error 必須修完，warning 必須逐條看過：

```bash
node <path-to-web-video-presentation>/scripts/validate-project.mjs <project-root>
```

任一未過 → 回去改。**不要**「先放著以後修」。
