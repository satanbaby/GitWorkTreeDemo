# 生成式插圖（ImageGen）

**什麼時候讀**：`outline.md` 該章寫了「插圖描述」時，**開發這一章之前**讀。
沒寫插圖描述的章節完全不用管這份文件。

---

## 0. 產出定位與邊界（先讀這條，最容易做錯）

要產出的是**跟主題同一套簡報視覺語言的場景插圖** —— 拿
`theme.json` 的 `styleReference` 當畫風錨點，讓每一章的圖看起來都屬於同一支
片子，而不是隨手一張通用 AI 圖。

> **生成的是插圖圖層，不是整張投影片。**
>
> 標題 / 清單 / 數字 / 總結文字**一律留在 HTML**。原因有三條，每條都是既有紅線：
>
> 1. 文字要跟著 step **逐步揭示** —— 燒進圖裡就只能一次全出
> 2. 顏色和字體家族**必須走主題 token** —— 圖裡的文字換主題就破
> 3. 生成圖的文字在 1920×1080 錄影下**必糊**，還常拼錯
>
> 所以：參考圖的「**版型**」由封面章節用 HTML 復刻（見
> [`CHAPTER-CRAFT.md`](CHAPTER-CRAFT.md) 的「封面章節（00-cover）」），
> 參考圖的「**畫風**」由這裡的生圖流程復刻。兩件事分開做。

---

## 1. 什麼該生成，什麼不該

| 該生成 | 不該生成（章節自己用 CSS / SVG / Canvas 畫） |
|---|---|
| 人物在做某件事（講解 / 協作 / 獨立工作 / 爭論） | 流程圖 / 架構圖 / 時序圖 |
| 有氛圍的場景（座位、會議、深夜、戶外） | 資料圖（長條 / 折線 / 排名） |
| 抽象概念的具象隱喻物（一把鑰匙、一座橋） | 對比表 / 清單 / 卡片矩陣 |
| 產品 / 器物的形象圖 | 終端機視窗 / 程式碼區塊 / 目錄樹 / 對話視窗 |

右欄是 [`CHAPTER-CRAFT.md`](CHAPTER-CRAFT.md)「每章必須有 CSS / SVG /
Canvas / JS 視覺演示」這條底線要求章節**親手畫**的東西。**拿生成圖頂替
= 驗收不過。** 生成圖是畫面的**氛圍層 / 角色層**，不是演示層。

---

## 2. 先查現成素材，別重複生成

主題 `theme.json` 若宣告了 `illustrations`（we-bare-bears 已有三張角色圖：
`grizzly-presenting` / `panda-reviewing` / `ice-bear-coding`），**先看這幾張
的 `bestFor` 能不能直接命中本步的情境**。能就直接用
`/theme-assets/<filename>`，不要重複生成一張幾乎一樣的。

新生成的圖**必須跟這幾張同一套畫風** —— 同一支片子裡兩種畫風打架，比沒圖更糟。

---

## 3. 生成時機

**Phase 2.4 開發該章之前**，不是提前批次生成、也不是邊寫邊補：

- 模式 A / B（主執行緒）：輪到這一章時，先生成圖，再動手寫章節程式碼
- 模式 C（平行 subagent）：**由該章自己的 subagent 生成自己的圖** ——
  路徑依章節 id 分目錄，不會互相覆蓋

---

## 4. Prompt 配方（以風格參考圖為錨點）

```
<風格錨點> + <內容：outline 的插圖描述原文> + <構圖限制> + <negative>
```

### 風格錨點 —— 優先餵參考圖

主題 `theme.json` 的 `styleReference.path`，實際檔案在
`themes/<theme-id>/assets/`（scaffold 已複製一份到
`<project>/public/theme-assets/`）。

- **圖片生成工具支援參考圖輸入** → 直接把這張圖餵進去，要求「沿用這張圖的畫風」
- **不支援** → 用 `styleReference.styleNote` + `descriptionZh` + `mood` 拼成
  文字前綴。以 we-bare-bears 為例：
  > 圓潤炭黑手繪輪廓、奶油紙底、天空藍與蜂蜜木色為主、淡紫／淡黃柔和幾何
  > 形狀點綴、平塗無寫實陰影、角色表情友善的繪本插畫風

`illustrations[].altZh`（如「熊貓拿著咖啡閱讀筆記」）是現成的**描述語氣範本** ——
照那個顆粒度寫內容部分就對了。

### 構圖限制

- 主體偏置一側，另一側留白給 HTML 文字（對齊參考圖「右側插圖 / 左側文字」的版面）
- 背景：透明，或主題的奶油底色（`--surface`）—— 方便合到舞台上不出白框
- 畫面內**不得有任何文字**（含招牌、按鈕標籤、UI 文案）

### Negative

文字 / 浮水印 / 假 logo / UI 截圖感 / 紫粉漸層 / 寫實照片風 / 3D 算圖質感 /
雜亂背景。

### 生成後目視比對

把新圖和 `styleReference` 及既有三張角色圖放一起看：**線條粗細、配色、
留白密度、有沒有陰影**四項對不上就重新生成。**不要將就** —— 畫風不一致
在錄影裡一眼看得出來。

---

## 5. 輸出與引用

| | 路徑 |
|---|---|
| 存檔 | `presentation/public/illustrations/<chapter-id>/<slug>.png` |
| 章節引用 | `/illustrations/<chapter-id>/<slug>.png` |

`<chapter-id>` / `<slug>` 直接取 outline 插圖描述那一行寫的值。

與 `/theme-assets/`（主題自帶的靜態素材）**平行、不混用**：
`theme-assets` 是跟著主題走、換主題會換的；`illustrations` 是跟著這支片子
的內容走的。

---

## 6. 工具無關 + 降級路徑

本 Skill 的 `manifest.json` 宣告相容多種 agent（claude-code / cursor /
codex-cli / gemini-cli / opencode），各家圖片生成工具不一樣：

1. **優先呼叫當前 agent 可用的圖片生成工具** —— Claude Code 用 ImageGen，
   其它 agent 用各自的等價工具
2. **呼叫不到 / 生成失敗** → **降級**：
   - 章節裡放 placeholder 佔位卡（依真實比例留位，卡上寫「illustration ·
     <一句描述>」）
   - `outline.md` 素材清單該條改標 `⚠️`（待提供）
   - **交付本章時明確告訴使用者「這張圖沒生成出來，現在是佔位卡」**

降級是**允許的**，隱瞞不是。這條對齊
[`CHAPTER-CRAFT.md`](CHAPTER-CRAFT.md)：**缺的東西承認缺，比 fake 強一百倍。**

---

## 7. 生成後回寫 outline

生成成功 → `outline.md` 末尾「素材清單」裡對應那條
`🎨 …（待生成 → …）` 就地改成：

```
- ✓ <描述>（`illustrations/<chapter-id>/<slug>.png`）
```

**不回寫 = 下一個 agent 會以為還沒生成，重複跑一次生圖。**
