# 熊熊情境插圖（ImageGen）

**什麼時候讀**：Phase 1 產生 outline 的 Illustration Pass，以及 Phase 2
開發任何帶有「插圖建議」的章節之前。

---

## 0. 不可破例的輸出邊界

> ImageGen 只產生**零文字的透明情境圖層**，絕不產生整張投影片。

- 圖內不得有文字、字母、數字、招牌、按鈕標籤、logo、浮水印、可讀程式符號
  或假 UI。純粹的汗滴、動作線與情緒線可保留，但不能長得像文字符號。
- 標題、清單、數字、結果與品牌名稱一律由 HTML / CSS / SVG 呈現。
- 流程圖、架構圖、資料圖、終端機與程式碼由章節用程式碼畫；生成插圖不能
  取代每章必要的視覺演示。
- 預設背景透明。只有透明輸出不可用時，才使用純 `--surface` 奶油底；不得
  生成完整背景、卡片、邊框或投影片構圖。

這條同時解決可讀性與穩定性：ImageGen 專注畫「誰在做什麼」，資訊層由瀏覽器
精準排版並隨 step 揭示。

---

## 1. Outline 的 Illustration Pass

產生 `outline.md` 時，先替**每個 step**判斷視覺類型，再決定是否建議生圖：

| 類型 | 使用時機 | ImageGen |
|---|---|---|
| `【情境插圖】` | 人物行動、情緒、協作、衝突、抽象隱喻 | 建議；另寫具體插圖建議 |
| `【程式演示】` | 流程、關係、資料、終端機、目錄樹、比較 | 不生圖 |
| `【真實素材】` | 產品畫面、截圖、照片、使用者提供的證據 | 不生圖 |
| `【文字構圖】` | 封面文字、金句、轉場、單一 hero 數字 | 通常不生圖 |

Illustration Pass 不是硬塞圖片。整體檢查時，至少檢視封面，以及每連續 2~3 個
內容章節是否存在一個值得用熊熊角色講清楚的**人類情境**；沒有就明確保留程式
演示，不為達配額生成裝飾圖。封面預設應有熊熊角色視覺錨點。

`【情境插圖】` 的 step 必須在章節資訊池後寫：

```markdown
**插圖建議**（CP-1 確認後才生成）:
- [step 3] `透明情境層｜主體靠右｜左側 40% 留白`：三位熊熊 coding agent
  同時伸手修改中央同一個資料夾，動作線互相交叉，表情從專注轉為錯愕；
  圖內零文字 → `illustrations/agent-risk/shared-folder-conflict.png`
```

描述必須包含：**角色／物件、可見動作、單一衝突焦點、主體位置與留白方向**。
只寫「團隊衝突」「很忙的工程師」太抽象，不足以穩定生成。

CP-1 前這些是建議，使用者可接受、刪除或改寫；CP-1 通過後，每條保留的建議
才成為章節開發前必須準備的素材。

## 2. 固定的熊熊畫風錨點

這個 Skill 只使用 `we-bare-bears` 視覺系統。先讀
`themes/we-bare-bears/theme.json`：

- `layoutReference` 只供封面 HTML 版型參考，**禁止餵給 ImageGen**。它含文字與
  完整版面，拿來生圖容易誘發帶字的全頁圖片。
- `illustrationStyle.goldenReference` 是情境構圖與畫風的主要參考。
- `illustrationStyle.characterReferences` 是角色比例、輪廓與配色參考。
- `illustrations` 是可直接重用的現成角色素材索引。

圖片工具支援參考圖時，至少提供：

1. `goldenReference`；
2. 本次會出現角色對應的 `characterReferences`。

不要把所有參考圖無差別塞入；只選本次需要的角色，降低角色混合與多餘肢體。
圖片工具不支援參考圖時，才退回 `illustrationStyle.styleNote` 文字錨點。

---

## 3. 先重用，再生成

先查 `theme.json` 的 `illustrations[].bestFor`：情境直接命中時，重用
`/theme-assets/<filename>`。只有下列情況才生成新圖：

- 兩位以上角色有明確互動；
- 需要特定道具或衝突焦點；
- 現成角色姿勢無法表達旁白動作。

一個 scene 最多一張插圖。角色不是角標、吉祥物貼紙或固定背景。

---

## 4. 穩定 Prompt 配方

使用以下順序，不要在 prompt 裡要求「做一張簡報」「做資訊圖表」：

```text
[任務] 產生一個可疊在網頁上的透明背景情境插圖圖層。
[角色與物件] <誰、幾位、中央唯一物件>。
[可見動作] <每個角色的手勢／姿勢／視線>。
[單一焦點] <觀眾一眼要看懂的衝突或情緒>。
[構圖] <主體在哪一側、另一側保留多少乾淨透明區>。
[畫風] 嚴格跟隨提供的熊熊參考圖：圓潤炭黑手繪輪廓、平塗、固定角色比例、
       奶油與蜂蜜木色為主、天空藍小面積點綴、無寫實光影、無 3D 質感。
[禁止] 任何文字、字母、數字、可讀程式／UI 符號、logo、浮水印、招牌、UI、卡片、投影片、
       完整背景、紫粉漸層；禁止多餘角色、多餘肢體與重複物件。
```

### Coding Agent 衝突頁的標準範例

```text
產生一個可疊在網頁上的透明背景情境插圖圖層。四位熊熊 coding agent 圍繞
中央唯一一個打開的專案資料夾，各自從不同方向伸手放入檔案或操作筆電，手勢與
動作線互相交叉；角色表情從專注轉為錯愕，讓觀眾一眼看懂「多人同時修改同一個
工作目錄」的衝突。主體集中在畫面右側 60%，左側 40% 保持完全透明供 HTML
標題使用。嚴格跟隨提供的熊熊參考圖。圖內零文字、零字母、零數字、零可讀
程式／UI 符號、零 logo、零 UI、零招牌、零卡片、零投影片版面；不要完整
背景、不要多餘角色或肢體。
```

關鍵不是在圖上寫 `same folder` 或 `mixed output`，而是用「四個方向 → 一個資料夾」
的剪影與動作說清楚；這些結果文字再由 HTML 疊上。

## 5. 生成、檢查與有限重試

1. 依 outline 指定的構圖生成一張。
2. 用圖片檢視工具在透明棋盤背景上看原圖，再放進實際 1920×1080 step 看一次。
3. 逐項檢查：
   - 圖內零文字／字母／數字／logo；
   - 角色數量、比例、輪廓粗細、臉部與配色符合參考圖；
   - 一眼看懂動作與單一焦點；
   - 留白方向正確，HTML 不會壓住臉或手勢；
   - 沒有完整背景、UI、卡片、多餘肢體或重複物件。
4. 失敗時，只針對具體失敗項 edit / regenerate；最多重試 2 次。不要每次大改整段
   prompt，避免畫風漂移。
5. 3 次都不合格就使用等比例 placeholder，素材清單標 `⚠️`，並在章節交付時
   告知使用者；禁止將就接入不合格圖片。

---

## 6. 輸出與引用

| | 路徑 |
|---|---|
| 存檔 | `presentation/public/illustrations/<chapter-id>/<slug>.png` |
| 章節引用 | `/illustrations/<chapter-id>/<slug>.png` |

- 保留透明背景時用 PNG 或透明 WebP；長邊以 1600px 左右為上限。
- 單張目標小於 1 MB；超過先壓縮，2 MB 以上不得直接交付。
- `<img>` 不得加 `loading="lazy"`，避免破壞 `PrefetchAhead`。
- 生成成功後將素材清單 `🎨` 改成 `✓` + 實際路徑；失敗改成 `⚠️`。
